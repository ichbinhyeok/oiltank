# Oil Tank Route operating instructions

## Property record-research operations

Before researching a customer case, read `ops/record_research_operations.md`, inspect the protected case desk, and review the relevant case's append-only activity history. The case desk and private files under `storage/operations` are the operational source of truth; email is evidence, not a replacement status database.

After every material intake, online finding, agency request, bounce, referral, reply, document receipt, customer update, delivery, or reusable route lesson, record a structured case activity in the same working turn. Always include the applicable route ID, agency/channel, source or request ID, outcome, next action, and check date when known. A drafted request is not a sent request, and a sent request is not an acknowledgment or delivery.

When a case changes state, update the case status and record the matching activity. When a case reveals durable agency knowledge, add a `route-lesson` activity first and then promote the verified non-PII lesson into the persistent route-intelligence override. Never put customer addresses, emails, narratives, or uploaded documents in route intelligence.

Keep uploaded documents and unredacted evidence inside ignored private storage. Never publish or commit the private case desk, activity ledger, document register, or customer files.

Do not send an agency or customer message merely because a follow-up date is due. External sending still requires explicit user authorization.
