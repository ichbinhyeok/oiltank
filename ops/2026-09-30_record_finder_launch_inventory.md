## Maintenance and release contract

- One `ResearchCatalog.Entry` drives detail SSR, finder, home task links, sitemap identity, admin freshness and worksheet source log. New content is in `RecordTasks` / `LaunchResearchAreas`, not an independent runtime DB.
- Existing `RecordsDataRepository` composite-key override merge remains compatible. Private overrides are not rewritten. Its diagnostic export now reports invalid overrides; incident parse failures no longer silently disappear from logs.
- Existing stable-key overrides also resolve matching detail-source URLs, labels, caveats and fallback notes before SSR; the worksheet reads the same resolved DOM. A regression rehearsal changes DataMiner once and verifies every matching research step. Ambiguous source matches are not guessed. Editorial procedural text still requires review when a procedure changes; a URL patch alone is not a procedure verification.
- Owner is responsible for review; new routes use a 90-day due date. Admin diagnostics expose due dates and assisted/self-service boundaries. No recurring job or external messaging created.
- No deployment/merge/sitemap submission is claimed by this file. Release requires final build/browser checks and normal private-backup/security gates. Do not restore private case data to roll back only an application release.
